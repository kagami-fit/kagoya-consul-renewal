# KAGOYA サイト更新管理

## 一言で言うと

Google スプレッドシートを編集画面として使い、KAGOYAサイトの更新・確認・公開・履歴保存を行う仕組みです。普段の担当者はHTMLやGitHubを触りません。

## 何ができるのか

- 「Today’s KAGOYA」「お知らせ」「物件」「進行中プロジェクト」を表から更新
- 全ページの文章、共通情報、使用画像を一覧で管理
- 入力漏れやURL・日付などを公開前に検証
- 「確認待ち」→「公開予約」→「公開中」の順で誤公開を防止
- 成約済み・非公開・画像の非使用を、通常公開と同じ確認手順で安全に反映
- 同じ項目の二重申請と、公開申請後に変更された内容の誤公開を防止
- 未来日時の公開予約と、大量データの分割配信に対応
- 公開前の内容を保持し、編集中の内容がサイトへ漏れないように分離
- 更新者・変更前・変更後・公開結果を履歴へ自動記録
- GitHub Actionsが公開済みデータだけを取得し、サイトへ自動反映

## 構成

- `gas/`：Google スプレッドシートに紐づく Apps Script
- `scripts/sync-from-feed.mjs`：公開済みデータをサイト用JSONへ変換
- `scripts/annotate-page-copy.mjs`：ページ文章の管理IDをHTMLへ付与
- `tests/run-local-tests.mjs`：状態遷移・成約分類・大量データ・JSON同期の安全テスト
- `schema/feed.schema.json`：公開データ形式の仕様
- `../.github/workflows/publish-cms.yml`：定期取得・検証・GitHub Pages反映

## 使い方

1. Google スプレッドシートの `02_Today`〜`08_画像` を開きます。
2. 黄色いセルへ内容を入力し、画像以外は「確認待ち」、画像は「差し替え待ち」にします。
3. メニュー「KAGOYAサイト更新」から「① 入力内容を確認する」→「② 確認待ちを公開申請する」を実行します。
4. `90_公開キュー`で変更概要を確認します。
5. 「③ 公開予約をサイトへ反映する」を実行します。
6. 通常10分以内にGitHub Pagesへ反映され、`99_更新履歴`へ記録されます。

詳しい日常運用は `運用マニュアル.md`、制作担当向けの接続方法は `初回設定メモ.md` にまとめています。
