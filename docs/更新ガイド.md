## 写真の差し替え

1. 新しい写真は`src/`へ分かりやすい英数字名で保存。元画像は削除しません。
2. 使用権・掲載許可を確認し、実績・実物件の写真と生成イメージを区別します。
3. JPGとWebPを併記している場所は両方を更新。JPGだけではWebPが優先され変更が見えません。
4. トップ8事業・事業一覧・詳細のヒーローを揃え、画像の説明文（alt）も更新します。
5. `SPEC.md`の採用画像表に記録。共有画像の上書きは他ページにも影響するため、新しい名前での追加を推奨します。

2026-09-16採用の「0912追加分」6枚は `src/client-0912-*.jpg`／`.webp`。トップ・事業一覧・詳細で共通使用します。エフクリの `business-image--fukuri` は文字の切れ・重なりを防ぐため維持してください。元のPNGは提供フォルダに残しています。

## 安全な再生成

事業ページの生成元を編集した場合だけ、順番に実行します。

```bash
node scripts/build_business_pages.mjs
python3 scripts/update_common_chrome.py
```

共通ヘッダー等だけの更新なら2行目のみで構いません。

`scripts/build_site.py`・`build_sample07_home.py`は初期生成用です。現在のトップ・写真・削除済みブロックを戻す可能性があるため、日常更新では実行しません。`apply_client_revision_20260916.py`は今回の一括変換の記録で、通常更新時には実行不要です。

## 確認してから公開

共有用URLは https://kagami-fit.github.io/kagoya-consul-renewal/ です。お問い合わせページは https://kagami-fit.github.io/kagoya-consul-renewal/contact.html です。`127.0.0.1:8765`の確認用URLは、このPC以外では開けません。

公開元はGitHubリポジトリ`kagami-fit/kagoya-consul-renewal`の`main`ブランチ・ルートです。2026-09-17に設定を確認済み。`main`へのpush後、GitHub Pagesのビルド完了を待って公開ページを確認します。ローカルファイルを保存しただけでは公開サイトは更新されません。

1. `git status --short`で既存の変更を確認し、別作業を混ぜない。
2. 下記の構文・回帰確認を実行する。
3. サーバーを起動し、PC・タブレット・スマホ幅で横はみ出し・重なり・改行・画像を確認する。
4. メニュー、ニュース絞り込み、事業リンク、電話・LINE・公式フォームの行き先を確認する。問い合わせのテスト送信は別途承認を得る。
5. 公開指示がある場合だけ、対象ファイルを明示してcommit・pushする。`.env`、認証設定、無関係な未追跡ファイルは含めない。
6. GitHub Pages反映後に公開URLで確認する。`?rev=コミット短縮ID`を付けると確認版を識別できる。

```bash
node --check assets/js/site.js
node scripts/test-site-contact.cjs
node scripts/test-listing-pages.cjs
node scripts/test-social-images.cjs
node scripts/test-business-images.cjs
git diff --check
python3 -m http.server 8765 --bind 127.0.0.1
```

データ更新時は日付・価格・面積・公開状態を事業者側で確認してください。物件一覧の件数は表示しない方針です。

## ナレッジとファイルの整理

- `SPEC.md`：現行の会社情報・事業名・公開表現・写真採用表。変更時は差分更新する。
- `docs/修正履歴_YYYYMMDD.md`：いつ・どのページ・どの範囲を変えたか。
- `docs/reference/`：旧手順の参考保管。そのまま実行しない。
- `_review/`・`outputs/`：スクリーンショット・一時出力。公開物と分ける。
- `src/`：公開画像。共有利用があるため、参照確認なしに削除しない。
- `HP設計書_確定.txt`・`site-design.md`：初期資料。相違時は最新ユーザー指示と`SPEC.md`を優先。
- 旧ZIP：以前の控え。納品時に最新の公開ファイルから作り直し、認証情報・内部CMS設定は混ぜない。

今回の整理はこのサイトのプロジェクト内に限定しています。PC全体・別案件のファイルは移動・削除していません。
